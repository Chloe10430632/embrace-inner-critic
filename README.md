# 擁抱內在批評者

> Embrace Your Inner Critic

一個低干擾且具有互動感的引導式反省日記網站，幫助使用者辨認內在批評者的聲音，逐步看見觸發情境、情緒、行為與過去經驗之間可能存在的模式。

## 為什麼做這個產品

一般筆記工具雖然彈性高，使用者卻需要自行「建立格式」、「標籤」與「整理流程」，也容易受到其他工作和通知干擾。

對不熟悉內在批評者的人而言，更困難的是不知道該記錄什麼，也可能把批評性的自動想法直接認成自己的身分或客觀事實。

「擁抱內在批評者」希望降低開始書寫與持續覺察的成本，讓使用者像探索一張自己的內在地圖，一次回答一個問題，不被要求寫得完整、正向或正確。

## 第一版產品範圍

第一版只做一項核心功能：**互動式引導反省日記**。

目前體驗如下：

1. 從一頁式首頁了解產品起點、內在批評者可能的形成脈絡、五階段練習方向與產品界線。
2. 透過簡短動畫認識內在批評者。
3. 使用者替自己的內在批評者取名。
4. 以簡短心理教育知道習慣的反應有機會透過練習改變。
5. 使用 Google 登入後，一次一題完成六個覺察步驟：
   - 什麼情況觸發了他？
   - 他說了哪一句感受最強烈的話？
   - 情緒受到了什麼影響？
   - 行為受到了什麼影響？
   - 這顆自我批判的種子可能讓我想到哪段較早的經驗？
   - 此刻可以如何轉化這個聲音？
6. 將草稿或完成紀錄儲存到帳號，並在完成後點亮一個新的地圖節點。

首頁同時說明完整方法的五個方向：識別、檢視、質問、重新定位與和解。目前可操作的日記聚焦前兩個階段；後三個階段仍在後續開發範圍，不宣稱已提供。

每一題都可以選擇「不知道」、「不確定」、跳過或中途停止。使用者的原始文字不由 AI 代寫、改寫或補完。

## 視覺與體驗方向

- 視覺：白、綠、黑。
- 字體：`Noto Sans TC`。
- 互動：獨立插畫角色進場、探頭與位移動畫，以及卡片切換、足跡前進與地圖節點點亮。
- 聲音：一首低干擾的正念冥想鋼琴背景音樂，以及輕柔可愛的按鈕音效。
- 自主性：動畫、背景音樂與按鈕音效都能關閉。
- 回饋：不使用排行榜、連續登入、失敗懲罰或愧疚式提醒。

## 心理安全與產品限制

本產品是自我覺察與紀錄工具，不提供心理疾病診斷、心理治療、醫療建議或危機介入，也不取代合格心理專業人員。

目前在開始書寫前與每個日記問題頁提供「我現在需要協助」入口，可手動前往台灣安全協助頁。自動安全文字攔截尚未實作；未來即使加入，文字規則也可能誤判或漏判，因此不宣稱系統能準確完成危機評估、即時監控或主動報警。

若使用者正處於立即危險，應優先聯絡台灣緊急服務 `119`／`110`、衛生福利部 [`1925` 安心專線](https://dep.mohw.gov.tw/DOMHAOH/cp-4906-54077-107.html)，或身邊可信任且能即時提供協助的人。

日記可能包含高度敏感的個人資料。正式公開前，需要完成必要的資料保護設計與安全測試。

## 預定技術架構

| 層級       | 技術                                                           |
| ---------- | -------------------------------------------------------------- |
| 前端       | Nuxt 4、Vue 3、TypeScript                                      |
| 樣式與互動 | Tailwind CSS 4、自訂 CSS、Vue Transition、Web Animations API   |
| 聲音       | HTML Audio、Web Audio API                                      |
| 後端       | ASP.NET Core 10 Web API                                        |
| 身分驗證   | ASP.NET Core Identity、HttpOnly Cookie                         |
| 資料存取   | Entity Framework Core 10                                       |
| 資料庫     | Supabase 託管 PostgreSQL                                       |
| 測試       | xUnit、ASP.NET Core integration tests；前端自動化測試待加入     |
| 協作       | GitHub、GitHub Actions                                         |

資料目前經由 `Nuxt → ASP.NET Core Web API → EF Core → PostgreSQL` 流動。瀏覽器不直接操作資料表；後端負責 Google Cookie 身分驗證、依登入者篩選日記、輸入與容量限制、分頁、每帳號日記額度、rate limit，以及 Cookie 寫入操作的 CSRF 驗證。自動安全文字攔截尚未實作。

## 在本機預覽前端原型

```bash
cd frontend
npm install
npm run dev
```

開啟終端機顯示的本機網址。瀏覽器 `localStorage` 只保存初次引導完成狀態與內在批評者名稱；建立或查看日記時需要 Google 登入，日記草稿與完成紀錄透過 ASP.NET Core API 儲存在 Supabase PostgreSQL，支援新增、讀取、修改及刪除。後端、本機 Secret 與資料庫設定請見 [backend/README.md](backend/README.md)。

可執行的前端驗證：

```bash
npm run typecheck
npm run build
```

## 測試環境部署

測試環境使用單一 Render Web Service，同一個 HTTPS 網址提供 Nuxt 前端與 ASP.NET Core API，資料庫沿用 Supabase PostgreSQL。部署步驟、Secret 清單、Google OAuth callback 與驗證方式請見 [DEPLOYMENT.md](DEPLOYMENT.md)。

## 專案狀態

第一個可操作的產品切片已完成，包含一頁式產品首頁、聲音選擇、插畫式心理教育動畫、角色命名、Google 登入、六題日記、標籤互動、草稿／完成紀錄 CRUD、回顧、節點點亮動畫及安全協助頁。首頁可使用系統分享功能，不支援時改為複製網址；Buy Me a Coffee 尚未設定正式連結。引導場景已改用獨立 PNG 插畫，角色可分層位移；初次登場則以小黑人從牆後探頭並搭配泡泡文字呈現。

背景音樂目前使用 CC0 授權的 `Mystical Piano`，在 1 分 35 秒處循環；來源與授權紀錄位於 `frontend/public/audio/CREDITS.md`。按鈕音效仍由 Web Audio API 即時產生。

目前已可使用 Google 登入並將日記儲存到 Supabase PostgreSQL；連線字串與 OAuth 憑證不進入版本控制。API 已加入登入者資料篩選、Cookie 寫入操作的 CSRF 驗證、rate limit、request size、分頁與每帳號 500 篇額度。安全頁可手動開啟，但尚未實作自動安全文字攔截；所有日記步驟仍需完成完整 RWD 與無障礙檢查。Render 設定與程式碼已存在，但遠端 migration、Google OAuth 與完整 CRUD 是否在測試環境端到端通過，仍須依 [DEPLOYMENT.md](DEPLOYMENT.md) 實際驗證。
